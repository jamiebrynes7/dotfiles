Codex 0.15x resolves a companion `codex-code-mode-host` binary next to its own executable (codex-rs/install-context: `code_mode_host_program_from_exe` falls back to `current_exe().parent()/codex-code-mode-host`). Our packages/codex derivation only installs `codex` from `codex-<triple>.tar.gz`, so every code-mode tool call (e.g. running a bash command) fails with 'codex-code-mode-host is missing'. Upstream issue: https://github.com/openai/codex/issues/31831

Upstream publishes `codex-code-mode-host-<triple>.tar.gz` per release, same shape as the codex tarball (single binary at root).

## Summary of Changes

- `packages/codex/hashes.json`: each platform now records a `codeModeHostHash` alongside the existing `hash`, regenerated by `update.sh` at 0.153.2.
- `packages/codex/default.nix`: swapped the single `src` for a two-element `srcs` list (codex + code-mode-host tarballs, both unpacking flat into `.`) and installs `codex-code-mode-host` into `$out/bin` next to `codex`.
- `packages/codex/update.sh`: factored the prefetch into a helper and fetches both artifacts per platform; a missing code-mode-host artifact fails the script, matching the packaging convention.

Verified: `nix build .#codex` produces both binaries, `codex --version` reports 0.153.2 and `codex-code-mode-host --help` runs. `nixfmt --check` and `shellcheck` clean.
