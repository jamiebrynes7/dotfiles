# Repo-wide formatting with treefmt — spec

Date: 2026-11-05

Move the repository's formatting gates onto treefmt, through the `treefmt-nix` flake
input, so that adding a formatter for another language later is one line of config
instead of a new check, a new hook branch and a new fix hint.

## Problem

Formatting is enforced in three hand-rolled places that each know about each language:

- the `nixfmt` flake check (`mkNixfmtCheck` in `flake.nix`);
- the `rust-fmt` flake check (crane's `cargoFmt` in `crates/default.nix`);
- `.githooks/pre-commit`, which picks `nixfmt --check` or `cargo fmt --all --check` by
  staged file extension and prints per-language fix commands.

Only Nix and Rust are formatted. The TypeScript plugins under `ts/`, the shell
`update.sh` scripts and the Lua nvim config are not, and adding any of them today means
touching all three places.

## Goals

- One formatter configuration, used by the flake check, the pre-commit hook, `nix fmt`
  and `treefmt` in the devShell.
- Exactly today's coverage: Nix through nixfmt and Rust through rustfmt, with no
  reformatting of existing files.
- Keep #421's selective CI behaviour: a PR that touches no formatted file leaves the
  formatting check's derivation path unchanged, so docs- and beans-only PRs still build
  nothing.
- The pre-commit hook stays check-only and never modifies the working tree.

## Non-goals

- **New languages.** TypeScript (biome or prettier), shfmt, stylua and Markdown
  formatting are later, separate changes.
- **Downstream consumers.** `lib.mkShells`, its `baseShellPkgs` and the project templates
  under `templates/` are unchanged; downstream projects keep the bare `nixfmt` they get
  today.
- **flake-parts.** The flake stays plain; treefmt-nix is used through `lib.evalModule`.
  flake-parts' treefmt module would save about ten lines of wiring, but adopting it means
  restructuring all of `outputs`. Its `perSystem` also assumes one nixpkgs, while this
  flake builds each platform's pkgs from a different input. That's its own change if it's
  ever wanted.

## Verified upstream behaviour

Checked against treefmt 2.6.0 (the version in `nixos-26.05`) and treefmt-nix at
`0d6d739a`.

- **treefmt has no check-only mode.** `--fail-on-change` and `--ci` both run the
  formatters in place and fail afterwards if anything changed. `--stdin` handles a
  single buffer, not a tree. This is what rules out calling `treefmt` from the hook.
- **`config.build.check` is `path -> derivation`.** It copies the given path, runs
  `git init`, `git add .` and a commit, runs `treefmt --no-cache`, then fails on
  `git diff --exit-code`. The input doesn't need to be a git repository, so a
  `lib.fileset.toSource` result works. `projectRoot` exists only in the flake-parts
  module, so there's nothing to configure for it here.
- **`projectRootFile` defaults to `.git/config`**, which exists after the check's
  `git init`, so a filtered source that drops `flake.nix` is safe.
- **`programs.rustfmt.edition` defaults to `"2024"`** and is always passed as
  `--edition`. treefmt calls `rustfmt` per file, so it never reads `Cargo.toml`. The
  workspace is on 2021, so the edition must be set.
- **`programs.rustfmt.package`** accepts any derivation with `bin/rustfmt`, including a
  rust-overlay toolchain.
- **`programs.nixfmt`** defaults to `pkgs.nixfmt`, which in `nixos-26.05` is nixfmt
  1.5.0, the same formatter `mkNixfmtCheck` uses now.
- **treefmt-nix's own `nixpkgs` input** is unused by `lib`. A `follows` keeps a second
  nixpkgs out of `flake.lock` and has no effect on evaluation.
- **Outside the check, treefmt walks files with git** (`git ls-files --cached --others
  --exclude-standard`), so gitignored paths such as `.direnv` and `target` are skipped,
  and it keeps a per-tree cache under the user cache directory.

## Design

### Flake input

Add `treefmt-nix` (`github:numtide/treefmt-nix`) with
`inputs.nixpkgs.follows = "nixpkgs"`. It's bumped with everything else by
`update-flake-lock.yml`.

### Configuration

A single treefmt-nix module at the repository root (`treefmt.nix`) is the only place
formatters are declared. `flake.nix` evaluates it once per system with
`treefmt-nix.lib.evalModule`, against the same per-platform pkgs it already builds
(`nixDarwinPkgs` and `nixOsPkgs`), so each platform formats with its own nixpkgs and the
config can see the overlay's `dotfiles.internal`.

- **nixfmt** is enabled with default options.
- **rustfmt** is enabled with:
  - `package` set to the pinned rust-overlay toolchain (`dotfiles.internal.rustToolchain`,
    already exported for the devShell), so treefmt formats with the same rustfmt as
    `cargo fmt` in the devShell;
  - `edition` read from the root `Cargo.toml`'s `workspace.package.edition` with
    `builtins.fromTOML`, so an edition bump is a one-place change.
- **Check fileset.** The same module declares the file extensions the check covers,
  hand-listed as `nix` and `rs`, next to the enabled programs. Adding a formatter later
  means adding its extensions here too. If that's forgotten, CI doesn't see those files.
- treefmt-nix's default excludes (lock files, `LICENSE` and similar) stay on.

### Flake outputs

- **`checks.<system>.treefmt`** is `build.check` applied to a
  `lib.fileset.toSource` of the repository filtered to the declared extensions. It
  replaces `checks.<system>.nixfmt`, and `mkNixfmtCheck` is deleted.
- **`rust-fmt` is removed** from `rustChecks` in `crates/default.nix`. Clippy and the
  tests stay with crane.
- **`formatter.<system>`** is `build.wrapper`, so `nix fmt` formats the tree.
- **The repository's devShell** adds `build.wrapper`, so `treefmt` is on `PATH`.
  `baseShellPkgs` keeps `nixfmt`, since it's shared with `lib.mkShells` and editors use
  it too.

### Pre-commit hook

`.githooks/pre-commit` stops calling each formatter. On every commit, it determines the
current system and builds `.#checks.<system>.treefmt` with `--no-link`. That makes the
hook check-only and identical to CI: same config, same formatter versions, same
fileset.

The hook no longer filters staged files by extension. The fileset in `treefmt.nix` is
the only list of formatted file types. A commit that changes no formatted file leaves
the check's `drvPath` unchanged, so the build is a store cache hit. The remaining cost
is a flake eval and a source copy on every commit, including beans-only ones. It's
accepted as a few seconds. If it proves annoying, the fix is to make the hook cheaper,
not to reintroduce a second extension list.

It checks what it checks today: the working-tree contents of files git knows about
(tracked or staged), because that's what a git flake's source contains.

The failure hint changes to a single fix command: run `treefmt` from the devShell, or
`nix fmt`.

### Documentation

- Root `CLAUDE.md`: the Commands entry for `nix flake check` (which names the `nixfmt`
  check), the `nixfmt <file>` entry (becomes `treefmt` / `nix fmt`), the pre-commit
  paragraph, and the Formatting section.
- `crates/CLAUDE.md`: drop `rust-fmt` from the list of gates and point Rust formatting at
  the repository's `treefmt` check.
- The `mkNixfmtCheck` comment in `flake.nix` goes along with the function.

## Error handling

- **Unformatted file:** the check fails with treefmt's `git diff` output naming the file
  and the change. In the hook, the build failure blocks the commit and the hint prints.
- **Edition or rustfmt mismatch:** this shows up as the check failing on files `cargo fmt`
  accepts. Verifying zero diff on the current tree (below) catches it before landing.
- **Hook run outside the devShell:** the hook needs only `nix`, which every machine has.
  The fix hint still points at the devShell for `treefmt`.
- **Hook eval failure** (a broken flake mid-edit): the `nix build` fails and blocks the
  commit, just as a broken flake fails CI. Bypass with `git commit --no-verify` as today.

## Testing seams

Everything is verified through the existing `nix flake check` and the CI changed-checks
mechanism. There are no new test harnesses.

- **Zero churn:** running `treefmt` (or `nix fmt`) on the current tree changes no
  files, and `checks.<system>.treefmt` builds green on both systems.
- **It catches each language:** a deliberately misformatted `.nix` file and a
  deliberately misformatted `.rs` file each fail the check and the hook.
- **Selective CI is preserved:** a change to a Markdown or bean file leaves
  `checks.<system>.treefmt`'s `drvPath` unchanged. A change to a `.nix` or `.rs` file
  changes it.
- **Nothing else moved:** apart from the removal of `nixfmt` and `rust-fmt` and the
  addition of `treefmt`, the set of check names is the same.
